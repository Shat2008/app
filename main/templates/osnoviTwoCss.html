Коментарі в CSS та структура коду

Навіщо потрібні коментарі

Коментарі в CSS — це пояснення в коді, які не впливають на його роботу. Вони допомагають програмісту та іншим розробникам розуміти, що саме робить певний фрагмент стилів.

CSS-коментар починається символами /* і закінчується */.


/* Це коментар, браузер його ігнорує */
p {
    color: blue; /* Цей коментар стоїть у рядку */
}

Коментарі не відображаються на сторінці, але суттєво підвищують зручність читання коду.

Правила оформлення коментарів

  • Використовуй коментарі для пояснення складних частин стилів.
  • Коротко підписуй логічні секції: шапка, навігація, контент тощо.
  • Не вставляй коментарі всередину значень (це викличе помилку).

/* --- Оформлення шапки сайту --- */
header {
    background-color: #0044cc;
    color: white;
}

/* --- Навігаційне меню --- */
nav a {
    text-decoration: none;
    color: white;
}

/* --- Основний контент --- */
.main {
    padding: 20px;
}

Структура CSS-коду

Хороша структура коду — це коли стилі впорядковані, читабельні та логічно розділені на секції. Це особливо важливо у великих проєктах, де десятки або сотні правил.

Приклад логічної структури:


/* 1. Глобальні стилі */
* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}

/* 2. Основне оформлення сторінки */
body {
    font-family: Arial, sans-serif;
    background-color: #fafafa;
    color: #333;
}

/* 3. Заголовки */
h1, h2, h3 {
    text-align: center;
}

/* 4. Посилання */
a {
    color: #0066cc;
}
a:hover {
    color: #003366;
}

/* 5. Підвал */
footer {
    text-align: center;
    font-size: 14px;
    color: gray;
}

Така структура робить код зрозумілим навіть через кілька місяців після написання.

Типові помилки при використанні коментарів

  • ❌ Забування закрити коментар (*/) — у результаті CSS може не працювати.
  • ❌ Коментар усередині іншого коментаря — так робити не можна.
  • ❌ Надмірна кількість коментарів — вони повинні бути корисними, а не дублювати очевидне.

Висновок

Коментарі допомагають тримати CSS у порядку, а структура — робить його зрозумілим для тебе та інших. Використовуй логічні розділи, зрозумілі підписи і не забувай, що чистий код — це завжди ознака професіоналізму.
